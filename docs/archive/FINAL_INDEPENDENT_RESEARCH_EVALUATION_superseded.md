## Executive Verdict

**FINAL VERDICT: C — STRONG RESEARCH ARTIFACT BUT EMPIRICALLY INCOMPLETE**

The LEGACY-CONTRACT repository contains a technically sound, scientifically honest, and well-implemented research platform for behavioral contract recovery from legacy JCL/COBOL artifacts. The static analysis pipeline (parsing, extraction, BCG construction, mutation testing, risk detection) is production-quality with 265/265 tests passing. However, three fundamental empirical gaps prevent external submission:

1. **RQ1 is circular** — Level-2 ground truth was generated by the same extractor under evaluation; F1=1.0 is an idempotency check, not accuracy measurement. Level-3 independent human annotation has not been conducted.

2. **RQ2 is incomplete** — The hypothesis (H2) references Baseline D (Dep+LLM) which has no results. The BCG+dynamic condition (the full proposed method) is blocked. Only the static conditions have been evaluated.

3. **RQ3's artifact_id mapping layer exists but is not wired into the pipeline** — The `artifact_mapping.py` module was created as a standalone file but is not imported or used anywhere in `src/`. Dynamic contract promotion is currently achieved only by accidental name-matching, not the deterministic architecture claimed.

The repository exhibits **exemplary scientific integrity**: ground truth circularity is fully acknowledged, all blocked conditions are properly labeled, no results are fabricated, and a Level-3 annotation protocol is prepared and ready. The manuscript's Discussion (§15), Ablation Study (§12), and Conclusion (§19) are complete with actual findings. The Related Work section cites W29–W36 including GIST, Ammons, Lo, SYMDIFF, and Daikon comparison table.

## RQ1 Evaluation

**Rating: C — Self-Consistency Only**

### What Was Done
The RQ1 evaluation measures whether the BCG static extractor achieves F1 ≥ 0.70 on the Level-2 DETERMINISTIC benchmark (463 items: 139 positive, 324 negative). The extractor achieves F1 = 1.00 (TP=139, FP=0, FN=0).

### The Core Problem
The Level-2 ground truth was constructed by running the same BCG static extractor and treating its output as the reference. This is a **closed-loop self-consistency check**, not an independent accuracy measurement. F1 = 1.0 is mathematically guaranteed when the evaluator and the evaluated are the same deterministic function applied to the same input.

### Consistency of Labeling
**The repository is CONSISTENT in acknowledging this.** Evidence:
- `rq1_summary.json`: `"verdict": "SELF_CONSISTENCY_ONLY"`, `"rq1_status": "BLOCKED_FOR_INDEPENDENT_VALIDATION"`
- `TABLE_4_rq1_recovery.md`: Bold ⚠️ header "SELF-CONSISTENCY EVALUATION — NOT INDEPENDENT ACCURACY"
- Paper §11 RQ1: Caveat present, explicitly states Level-2 is circular
- `rq1_summary.json`: Explicit note "DO NOT cite F1=1.0 from this experiment as evidence of extraction accuracy"

### Remaining Inconsistency
Paper §11 line 467 states "**H1 (F1 ≥ 0.70, Precision ≥ 0.75) is supported.**" The caveat appears on the next line (469) but the headline claim appears without qualification. This creates a headline/body mismatch that will confuse reviewers.

### What Is Needed
Level-3 independent human annotation:
- ≥ 2 qualified JCL/mainframe annotators
- Blinded to extractor output (protocol: `docs/annotation_blinding_protocol.md`)
- Package generation: `scripts/export_blinded_annotation.py` (ready)
- Import: `scripts/import_annotation_results.py` (ready)
- Inter-annotator agreement κ ≥ 0.60 required

**benchmark/annotations/ is empty.** Level-3 annotation has NOT been conducted.

### Additional Concerns
- RESOURCE contract type: n=3 positive instances. No per-type claim is warranted.
- FPR is undefined (open-set — no ground-truth negative universe labeled for obligation-free JCL).
- Generalization: OMP public COBOL shows F1=0.0 (GT coverage gap, not extraction failure — but still unresolved).

## RQ2 Evaluation

**Rating: PARTIAL (Static conditions evaluated; hypothesis untestable as stated)**

### What Has Been Run
| Condition | Status | F1 |
|---|---|---|
| Baseline A (structural dependency) | COMPLETE | 0.8878 |
| Baseline B (complexity metrics) | COMPLETE | 0.0000 |
| Baseline E (static BCG-only) | COMPLETE | 0.9619 |
| Proposed (static BCG + BCGDiff) | COMPLETE | 1.0000 |
| Baseline C (LLM-only) | BLOCKED — no API key | [RESULT_PENDING] |
| Baseline D (Dep+LLM) | BLOCKED — no API key | [RESULT_PENDING] |
| BCG+dynamic (proposed full method) | BLOCKED — artifact_id wiring gap | [RESULT_PENDING] |

### The Hypothesis Design Problem
H2 (paper §4) states: "The BCG + dynamic evidence system (E6) achieves higher F1 than the best baseline (Baseline D)." This hypothesis is **doubly unreachable**:
1. Baseline D has no results; it cannot be the comparator.
2. Static BCG already achieves F1 = 1.0 (ceiling); BCG+dynamic cannot exceed 1.0.

If static BCG already achieves maximum F1 on this benchmark, then "BCG+dynamic improves F1 by 10pp" is mathematically impossible. The hypothesis should be reformulated as: (a) FPR reduction, (b) precision on negative set, or (c) F1 on an extended benchmark with negatives.

### Ground Truth Circularity in RQ2
FP = 0 by design (rq2_summary.json: "all mutations are applied to valid BCGs"). The mutation benchmark has **no true negatives** (JCL changes that preserve contracts). Therefore:
- FPR = undefined (`"fpr": null` throughout)
- F1=1.0 is not surprising; it reflects design, not achievement

### The Real Finding
The discriminating result is ALTER_ERROR_BRANCH: proposed F1=1.00 vs. Baseline E F1=0.00. This demonstrates that confidence-delta detection (`diff.modified`) catches a class of behavioral weakening that pure broken-contract detection (`diff.broken`) misses. This is a real and valid architectural finding.

### "4 of 8 Operators Invisible" Claim
The paper's abstract claims "four of eight mutation operators completely invisible to structural analysis." A careful review of per-operator results shows this is not fully accurate:
- F3 operators (SUPPRESS_RC_CHECK, ALTER_ERROR_BRANCH): Baseline A F1 = 0.0 ✓ invisible
- Some F2 operators: Baseline A F1 = 0.0 ✓ (CHANGE_DATASET_NAME, ALTER_FILE_DEPENDENCY_ORDER)
- F1 operators: Baseline A F1 = 0.93–1.0 ✗ NOT invisible

The correct claim is: "Two F3 operators and two semantic-F2 operators are invisible to structural analysis; the remaining four operators are at least partially detectable." The abstract overstates this as "four of eight."

### What RQ2 Actually Proves
1. ✓ Static BCG detects all 8 mutation operator types on CardDemo JCL.
2. ✓ Structural dependency analysis cannot detect semantic contract violations (F3, semantic-F2).
3. ✓ Confidence-delta detection (MODIFIED contracts) catches a class missed by static-BCG-only.
4. ✗ Does not prove H2 (Baseline D missing; dynamic blocked).
5. ✗ Does not measure FPR (open-set; no ground-truth negatives).

## RQ3 Evaluation

**Rating: C — Infrastructure Demonstrated, Not Validated**

### What the Results Show
`rq3_dynamic_results.json` (run after GnuCOBOL 3.2.0 became available):
- 63 contracts processed across 33 JCL files
- 31 STATIC_DYNAMIC_SUPPORTED (49.2%)
- 1 STATIC_DYNAMIC_CONFLICT
- 31 NOT_OBSERVED

### Critical Structural Problem: artifact_mapping.py Is Not Wired
A new module `dynamic_analysis/artifact_mapping.py` was created as the C1 fix. It provides deterministic program→step→entity mapping with proper EXACT/AMBIGUOUS/MISSING status. Its 11 unit tests all pass.

**However, it is not imported or used anywhere in `src/`.**

Current reconciliation (`run_dynamic_reconciliation.py` line 94) uses a fallback: `artifact_id=ev_dict.get("artifact_id", data.get("program", ""))`. For JCL simulation traces, this falls back to the trace's top-level `program` field (e.g., "CARDFILE"), which happens to match some contract job-level names. The 31/63 SUPPORTED contracts were promoted by this **accidental name-matching**, not by the deterministic mapping architecture.

### What the 49.2% Actually Represents
- 11 of 13 usable traces are EXECUTION_SIMULATED — derived from JCL parser output, NOT real execution
- These traces record step ordering (JOB_START/STEP_START/STEP_END), not program behavior
- The 31 SUPPORTED contracts are almost exclusively TEMPORAL PRECEDES contracts matched by step sequencing
- CONTROL_FLOW coverage: 15.4% (most error paths not exercised — "happy path" traces only)
- RESOURCE coverage: 28.6%

### The CONFLICT
One CONTROL_FLOW contract (STEP04 MUST_HANDLE_RC when RC >= 8 → ERRHANDL) was contradicted by trace_009 (GnuCOBOL EXECUTION_SIMULATED). STEP04 returned RC=12 but execution did not branch to ERRHANDL. Three explanations remain unresolved: static extraction error, GnuCOBOL vs z/OS semantic divergence, or trace instrumentation gap.

### rq3_summary.json vs rq3_dynamic_results.json Inconsistency
`rq3_summary.json` still shows `"status": "[RESULT_PENDING]"` while `rq3_dynamic_results.json` has actual results. This is a documentation inconsistency (stale file, not fabrication), but it will confuse reviewers.

### H3 Hypothesis Problem
H3 requires FPR comparison between static and BCG+dynamic. FPR is undefined in the mutation benchmark (no ground-truth negatives). H3 cannot be tested as stated with the current evaluation design.

## Mutation Framework Evaluation

**Rating: 8/10**

### Strengths
- All 8 operators are fully implemented and applied to real JCL files
- Each operator has `source_evidence_ref` linking to documented real-world modernization failures
- F1 (job ordering), F2 (resource availability), F3 (return-code propagation) categories are empirically grounded
- MutationNotApplicable is correctly raised when a JCL lacks required structure (N/A=331/440, 75%)
- Mutation records include full provenance (mutation_id, failure_category, affected_entity_ids, original_state, mutated_state)

### Concerns
1. **75% N/A rate**: CardDemo JCL is sparse in F2/F3 structure. This is legitimate by design but the paper does not explain it explicitly. Reviewers will question benchmark representativeness.
2. **Circular design**: Mutations are designed to violate exactly the contracts BCG extracts. F1=1.0 is the expected outcome when the mutation framework and the detector are co-designed. A blind mutation set (designed without knowledge of the detector) would be a stronger evaluation.
3. **ALTER_ERROR_BRANCH requires post-hoc insight**: The operator reduces confidence by exactly 0.30 to exceed the 5% delta threshold. This was tuned to expose the MODIFIED detection mechanism. A reviewer may note this is not an independent evaluation.

## Scientific Integrity Evaluation

**Rating: 8/10**

### What Is Correctly Enforced
- NOT_OBSERVED ≠ CONTRADICTED: enforced in ReconciliationEngine and tested in 15+ tests ✓
- HUMAN_VALIDATED / GROUND_TRUTH states are terminal: tested in SI-07, SI-12 ✓

- Provenance survives BCGDiff: SI-02 tests pass ✓

### What Is Incompletely Enforced

**SI-01: SYNTHETIC_STATIC guard — PARTIALLY BROKEN**

The `all_synthetic=True` flag is recorded in `ReconciliationRecord.metadata` AFTER the reconciliation outcome has been determined. The `_update_contract()` method checks this flag before updating the validation state. However, the reconciliation logic itself can produce SUPPORTED outcome from synthetic events before the flag check, meaning a SYNTHETIC_STATIC trace can still logically produce SUPPORTED classification that gets checked and blocked — but the check happens *after* outcome determination rather than *before*. One test variant `test_synthetic_static_cannot_upgrade_to_supported` fails. This is a real scientific integrity gap.

**Full 265/265 tests pass** only because the specific failing variant was not included in the main test suite or the test structure obscures it. The stated "48 scientific integrity tests pass" claim requires verification against the specific SI-01 failure pattern.

## What Is Weak

1. **Ground truth validity (RQ1)** — This is the primary weakness. Without Level-3 independent annotation, the paper cannot claim to have measured contract recovery accuracy. The tautological F1=1.0 result could be eliminated as a finding; the system's value must come from RQ2.

3. **artifact_mapping.py isolation** — The C1 fix was created but not integrated. The module demonstrates good architectural thinking (11 tests, EXACT/AMBIGUOUS/MISSING taxonomy) but its existence in isolation makes the dynamic pipeline's 49.2% result depend on accidental name-matching rather than the claimed deterministic architecture.

4. **Dynamic evidence scale** — 2 real EXECUTION traces + 11 JCL-parser-derived EXECUTION_SIMULATED traces against 63 contracts across 33 JCL files is insufficient for any production-validity claim. This is proof-of-concept, not validation.

5. **Generalization** — The repository has a single primary dataset (CardDemo). The OMP F1=0.0 result reflects missing GT, not failing extraction, but regardless there is no independent cross-system validation.
