# Annotation Blinding Protocol
## LEGACY-CONTRACT — Ensuring Ground Truth Independence

**Document purpose:** Define the blinding procedures that prevent contamination of
Level-3 human annotations by algorithm output.

**Principle:** A ground truth is independent only if the annotator's judgment cannot
have been influenced by the system's prediction. This document specifies exactly what
information must be withheld and how the blinding is enforced.

---

## 1. The Blinding Problem

The Level-2 benchmark was generated by the BCG static extractor. Any annotator who has
seen the extractor's output — even informally, even as examples — may be anchored to
the extractor's categorizations. This is a subtle but serious form of contamination.

Even if an annotator does not consciously use the extractor's output, prior exposure
can influence which patterns they notice or how they classify ambiguous cases.

---

## 2. What Must Be Hidden From Annotators

The annotation package **must not contain** the following:

| Information | Reason |
|---|---|
| BCG extractor output (any form) | Direct contamination |
| Extracted contract JSON | Direct contamination |
| Contract IDs from the BCG | Could reveal expected answer |
| Confidence scores | Would anchor annotator toward system's confidence |
| Validation states (STATIC_CANDIDATE, etc.) | Would reveal whether system extracted a contract |
| Mutation labels (F1, F2, F3) | Would reveal the system's classification |
| Per-operator results from RQ2 | Would reveal system performance patterns |
| Any result from RQ1 | Would anchor expected precision/recall |
| The paper draft | Would reveal framing and expected contract types |

---

## 3. What May Be Shown to Annotators

| Information | Rationale |
|---|---|
| Raw JCL source excerpts | The artifact being annotated |
| Surrounding context (±20 lines) | Required for semantic interpretation |
| Contract taxonomy (TEMPORAL/RESOURCE/CONTROL_FLOW) | Required to complete the form |
| Annotation instructions | Required to perform the task |
| Example contracts from **different, non-benchmark JCL** | Training only, not from benchmark |
| The annotation form schema | Required to record findings |

---

## 4. Annotator Isolation Requirements

1. Annotators must not have access to the repository during annotation
2. Annotators must not have access to `benchmark/ground_truth/level2_deterministic.json`
3. Annotators must sign a blinding declaration before receiving the annotation package
4. The annotation package is prepared by `scripts/export_blinded_annotation.py`,
   which strips all system-generated fields before export
5. Annotators submit completed forms to the protocol coordinator, not to the repository
6. The protocol coordinator runs `scripts/import_annotation_results.py` to import
   results after both annotators have completed their work independently

---

## 5. Blinding Declaration Template

Annotators must sign or electronically acknowledge the following before receiving items:

> I confirm that I have not seen, read, or been briefed on:
> (a) the output of any automated contract extraction algorithm applied to the CardDemo JCL corpus;
> (b) any benchmark containing extracted contracts from the CardDemo JCL corpus;
> (c) any experimental results from the LEGACY-CONTRACT system.
>
> I agree to complete my annotation independently without consulting other annotators
> until the protocol coordinator has received and locked both annotation sets.
>
> Annotator ID: ____________________
> Date: ____________________

---

## 6. Package Preparation Checklist

Before releasing the annotation package, verify:

- [ ] All items in the package are exported by `scripts/export_blinded_annotation.py`
- [ ] No `contract_id`, `ground_truth_label`, `validation_state`, or `confidence_score`
      field appears anywhere in the exported items
- [ ] All file paths in the package use dataset-relative paths (no absolute machine paths)
- [ ] The package has been reviewed by the protocol coordinator for inadvertent leakage
- [ ] The blinding declaration has been signed by both annotators

---

## 7. Post-Annotation Verification

After importing results, verify:

- [ ] Each annotator completed items independently (submission timestamps do not suggest collaboration)
- [ ] Inter-annotator agreement (κ) has been computed before comparing with Level-2 results
- [ ] No annotator changed their responses after the other annotator's responses were known
- [ ] Adjudication (if required) was performed by a third annotator who did not see which
      response came from which annotator
