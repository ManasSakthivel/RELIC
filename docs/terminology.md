# Canonical Terminology — LEGACY-CONTRACT

This document defines the authoritative terminology used throughout the codebase,
documentation, and manuscript. All other documents defer to these definitions.

---

## Core Concepts

**Behavioral Contract Graph (BCG)**  
The formal intermediate representation encoding behavioral obligations across JCL and COBOL
artifacts. Defined as the 6-tuple `BCG = (V, E, C, P, D, Γ)`. Not a visualization tool —
a queryable formal structure.

**BCG** (abbreviation)  
See Behavioral Contract Graph above. Used after first mention.

**ExecutionEvent**  
A normalized record of a single observable event produced by running a COBOL program under
GnuCOBOL instrumentation. Fields: `artifact_id`, `event_type`, `timestamp`, `return_code`,
`input_datasets`, `output_datasets`, `trace_id`. Schema defined in
`src/legacy_contract/dynamic_analysis/model.py`.

---

## Contract Types

**TEMPORAL**  
A contract asserting a required execution ordering between two artifacts or steps.
Example: `A MUST_PRECEDE B` — step A must complete before step B executes.

**RESOURCE**  
A contract asserting a dataset availability or disposition obligation.
Example: `A PRODUCES ds CONSUMES ds` — step A must produce dataset `ds`; step B must
consume it.

**CONTROL_FLOW**  
A contract asserting a return-code guard or conditional execution obligation.
Example: `COND=(4,GT,STEP01)` — step B is skipped if STEP01's return code exceeds 4.

## Validation States

These states are mutually exclusive. Every contract has exactly one validation state.
Transitions are one-way (no downgrade of human-validated contracts).

**STATIC_CANDIDATE**  
Default state for a newly extracted contract. Evidence comes from static analysis only;
no dynamic evidence has been evaluated.

**STATIC_DYNAMIC_SUPPORTED**  
Static contract corroborated by at least one execution trace. Dynamic evidence does not
contradict the static extraction.

**STATIC_DYNAMIC_CONFLICT**  
Static contract contradicted by dynamic evidence. The observed runtime behavior violates
what the static analysis predicted.

**NOT_OBSERVED**  
Dynamic evidence was collected but the relevant execution path was never executed. The
contract cannot be confirmed or denied from available traces. Semantically distinct from
`STATIC_DYNAMIC_CONFLICT` — absence of observation is not evidence of contradiction.

**INSUFFICIENT_EVIDENCE**  
Trace coverage falls below the configured threshold (e.g., < 10% coverage). The engine
declines to make a validation determination.

**ENVIRONMENT_DEPENDENT**  
The contract's truth value depends on runtime environment factors (DB2 tables, CICS
transaction state, IMS segments) that are not observable from COBOL execution alone.

**EXECUTION_ERROR**  
The program terminated abnormally during trace collection. Validation state is undefined.

**HUMAN_VALIDATED**  
A human annotator has reviewed and confirmed or overridden this contract. This state is
protected — automated reconciliation must not alter it.

**GROUND_TRUTH**  
A contract marked as authoritative ground truth for evaluation purposes. Same protection
rules as `HUMAN_VALIDATED`.

## Evidence-Related Terms

**provenance**  
The record of how, where, and by what method a contract was extracted. Every contract carries
a `ProvenanceRecord` containing: `source_artifact`, `source_location`, `extraction_method`,
`confidence`, `validation_state`, `annotator` (if human-validated), `timestamp`.

**ConfidenceVector**  
A four-dimensional evidence weight vector: `[syntactic_evidence, semantic_evidence,
dynamic_evidence, human_signal]`. Weights sum to 1.0. The scalar confidence score is their
weighted sum. **Not a probability** — a calibrated ordinal score.

**SYNTHETIC_STATIC**  
A trace event generated by rule application rather than actual program execution. Explicitly
prohibited from being used to promote a contract's validation state. Enforced by SI-01 guard.

## Mutation Framework Terms

**mutation operator**  
A transformation applied to a JCL/COBOL artifact to simulate a contract-violating
modernization change. Operators are grounded in documented real-world failure cases.
Eight operators are defined: F1 (job ordering), F2 (resource/dataset), F3 (return-code).

**mutation category**  
F1 = temporal ordering failures; F2 = resource availability failures; F3 = control-flow
and return-code propagation failures. Categories defined in `docs/failure_taxonomy.md`.

**BCGDiff**  
The delta between two BCG states (before and after mutation). Used by the risk detector
to identify violated, preserved, or weakened contracts.

---

## Evaluation Terms

**Level-2 DETERMINISTIC ground truth**  
Contracts extracted by the deterministic extractor and treated as the evaluation benchmark.
Tautology warning: ground truth annotated by the same extraction family being evaluated.
A perfect score on such a benchmark confirms idempotence, not semantic correctness (this is why the legacy RQ1/RQ2 results are withdrawn).

**Level-3 human-annotated ground truth**  
Contracts independently annotated by domain experts with no access to the extractor's output.
Planned as future work; required for non-circular RQ1 validation.

**[RESULT_PENDING]**  
Scientific integrity marker. Indicates an experimental result that has not yet been computed.
**Must not be replaced with a fabricated value.** All `[RESULT_PENDING]` entries remain
until the corresponding experiment actually runs and produces output.

## Terminology Antipatterns

The following synonyms appear in older documents and should not be used in new writing.
Replace with the canonical terms above.

| Avoid | Use instead |
|-------|-------------|
| behavioral contract graph | Behavioral Contract Graph / BCG |
| execution event | ExecutionEvent |
| static candidate | STATIC_CANDIDATE |
| supported | STATIC_DYNAMIC_SUPPORTED |
| conflict | STATIC_DYNAMIC_CONFLICT |
| not observed / unobserved | NOT_OBSERVED |
| insufficient evidence | INSUFFICIENT_EVIDENCE |
| human validated | HUMAN_VALIDATED |
| ground truth item | GROUND_TRUTH |
| provenance record | ProvenanceRecord |
| confidence vector | ConfidenceVector |
| mutation op / mutop | mutation operator |
| pending result | [RESULT_PENDING] |
