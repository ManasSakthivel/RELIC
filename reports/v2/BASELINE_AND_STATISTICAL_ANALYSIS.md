# Baselines and statistical evaluation: RELIC vs trivial rules on JCL-SemBench (and the old benchmark)

Agent 4, RELIC final sprint. Tables are generated by `results/sembench/make_report.py` from `results/sembench/{metrics,paired_tests}.json` and `predictions.jsonl` (produced by `python -m relic_eval.sembench_eval`); numbers in the prose are read from the same files.

## 1. Bottom line

* **On JCL-SemBench (180 cases) RELIC V2 is not better than trivial text rules; the best trivial rule is significantly better.** RELIC is a *high-precision / low-recall* detector (ALL: precision 0.92, recall 0.25, specificity 0.98, FPR 0.02); the text rules are the reverse (recall 0.84 on ALL and 1.00 on the validated subset; specificity 0.11-0.68). ALL, abstain = not flagged: MCC `relic_v2` 0.324 vs `normalized_text_A` 0.451, `normalized_text_B` 0.525, `textdiff_ignore_job_parameters` 0.302, `textdiff` 0.176. Against `normalized_text_B` the trivial rule wins on per-case correctness (26 vs 55 discordant, exact p = 0.0017, **Holm p = 0.020**, ΔMCC -0.20 [-0.30, -0.10]). Against `normalized_text_A` the point estimate also favours the trivial rule but does not survive Holm (p = 0.025, Holm 0.172). Against `textdiff_ignore_job_parameters` and `textdiff` there is no difference in correctness (Holm p = 1 / 1).

* **RELIC V2 = RELIC v1.1 on SemBench: identical predictions on all cases** (0 + 0 discordant; both 23 TP / 2 FP / 70 FN / 85 TN). The V2 fixes (D-001..D-004), which help on the old development benchmark, produce **no measurable gain on SemBench**.

* RELIC v1.1/V2 vs v1.0: v1.0 is never better (8 vs 0 discordant, exact p = 0.0078; Holm-adjusted 0.078, not significant at the family level).

* **Old (development) benchmark, for context:** V2 beats v1.1 (27 vs 2 discordant, Holm p = 1.4e-05) and `textdiff` (41 vs 18, Holm 0.0114), but is *significantly worse* than `textdiff_ignore_job_parameters` / `normalized_text_A/B` (2 vs 18 discordant, Holm p = 0.0024): every fault mutant there changes the text, so the trivial rules reach recall 1.0 with 2 FP.

* These are negative / unfavourable results for the claim that RELIC adds accuracy over trivial rules; they are reported as found. What RELIC does offer is specificity/precision (§6). Caveats (16 clusters, labels not independently reviewed, contested labels, benchmark authored in-project) are in §8.

## 2. Protocol

* **Benchmark:** `benchmarks/sembench/cases.jsonl` (180 cases, sha256 `fc8e64ba9999cb3803ff8bfbc5a0d6e39792c128ae960a1478e20f6430bb162d`), `MANIFEST.sha256` sha256 `e73db790fc23da2d1756319b3ec0d461b180c194f42d14e0d52744612d2cf87b` (360 file entries; every entry re-hashed before use; each case's `original_sha256`/`transformed_sha256` also checked). 93 cases are `CHANGING`, 87 `PRESERVING`, in 12 categories / 68 subcategories and **16 base programs (`base_id`)**.
* **Labels** come only from the benchmark field `expected_outcome` (CHANGING = genuine behavioural change = positive class); never from a detector. Detectors receive only `(original text, transformed text, original path)`.
* **Subsets (reported separately, none dropped):** ALL (180); `VALIDATED_BY_ORACLE_AND_ARGUMENT` (151: the oracle agrees with `expected_outcome`); `ORACLE_DISAGREES` (28: the oracle contradicts it; 25 labelled CHANGING but judged EQUIVALENT, 3 labelled PRESERVING but judged DIFFERENT). The remaining 1 case (`ORACLE_ABSTAINS`) is only in ALL.
* **Detectors (8):** `raw_text`, `textdiff` (existing), `textdiff_ignore_job_parameters` (existing), `normalized_text_A` (no operand reordering), `normalized_text_B` (keyword-operand sorting) - rules in [`NORMALIZED_TEXT_BASELINE.md`](NORMALIZED_TEXT_BASELINE.md), frozen before any case was loaded (`results/sembench/BASELINE_FREEZE.json`, verified at run time); `relic_v1_0` = `RelicDetector(legacy_v1_0=True)`, `relic_v1_1` = `RelicDetector(False)`, `relic_v2` = `RelicDetector(False, v2=True)` - frozen, untouched, not tuned.
* **Abstention:** a detector exception / no prediction is a visible `ERROR`/`ABSTAIN` (empty or non-UTF-8 input: `UNSUPPORTED`), never silently negative. Two scorings are computed everywhere: *abstain = not flagged* (primary) and *abstain excluded* (coverage reported; paired tests use jointly covered cases).
* **Intervals:** Wilson 95% for proportions (ignores clustering, so optimistic); cluster bootstrap by `base_id`, 10,000 resamples, fixed seed 20261004, percentile 95%, the *same* resamples for every detector/pair (so paired differences are paired). Resamples in which MCC is undefined (an empty margin) are excluded and counted in `n_undefined_reps`.
* **Paired tests:** exact two-sided McNemar (binomial) on per-case correctness (prediction = label), 14 pairs per (subset, scoring) family, Holm-Bonferroni across the family; effect sizes: Δaccuracy, ΔMCC, Δbalanced accuracy, ΔF1 (paired cluster-bootstrap CIs), Cohen's g, Haldane discordant odds ratio. Class-wise McNemar p-values are in `paired_tests.json` (exploratory, unadjusted).
* **Verdict rule (fixed in advance):** a RELIC detector is *distinguishable* from a trivial rule only if Holm p < 0.05 **and** the paired bootstrap CI of ΔMCC excludes 0 in the same direction.

Total non-OK statuses across all 8 detectors and 180 cases: **0** (`status_counts_all_cases`: `raw_text` OK=180, `textdiff` OK=180, `textdiff_ignore_job_parameters` OK=180, `normalized_text_A` OK=180, `normalized_text_B` OK=180, `relic_v1_0` OK=180, `relic_v1_1` OK=180, `relic_v2` OK=180). These are scored as ordinary 'not flagged' (not abstentions).

1. **SemBench, all cases: no improvement over trivial rules was found; in one comparison the trivial rule is significantly better.** `normalized_text_B` beats RELIC V2 (accuracy 0.761 vs 0.600; Holm p = 0.020). No other RELIC-vs-trivial comparison is significant after Holm. 2. **Validated subset:** RELIC's MCC (0.475) is below `normalized_text_A` (0.647) and `_B` (0.715) and close to `textdiff_ignore_job_parameters` (0.518); no comparison against a non-degenerate rule reaches Holm significance in either direction; `raw_text` is beaten (exact p 0.0073, Holm 0.088).

3. **What RELIC does buy:** specificity/precision. FPR 0.02 vs 0.32-0.89 for the text rules; precision 0.92 vs 0.50-0.74 (validated subset: precision 1.00, FPR 0.00). It pays in recall (0.25 vs 0.84; validated 0.34 vs 1.00). A fair framing: RELIC is a conservative alert filter, not a more accurate equivalence classifier than trivial text rules on this benchmark.

4. **V2 vs v1.1:** indistinguishable (identical outputs); the old-benchmark gain of V2 does not transfer.

5. **Old benchmark (development set, context only):** V2's improvement over v1.1 is large and highly significant; but the normalised / ignore-JOB text rules beat V2 (2 vs 18 discordant, Holm 0.0024), because every fault mutant alters text and the harmless mutants differ only in comments or JOB parameters. That benchmark could never show RELIC ahead of a text rule on accuracy.

## 8. Limitations and threats to validity

* **Only 16 independent clusters (`base_id`).** Cluster-bootstrap intervals are wide and unstable for small subsets; McNemar p-values ignore clustering and are optimistic.
* **Labels are not independently reviewed** (`independent_review_status = PENDING` for all cases). 28 cases are contested by the oracle (25 'CHANGING' cases the oracle judges equivalent); they are included in ALL and reported separately. The validated subset is validated only by the project's own oracle plus a written argument, not by an external reviewer.
* **Benchmark composition drives the aggregate.** 12 categories (6 preserving, 6 changing) were designed by the benchmark author (another agent) inside the same project; text rules do well where genuine changes leave visible textual diffs and badly on semantically-neutral syntax variants RELIC ignores; RELIC's blind spots (return codes, DISP, many dataset/COND edits) are equally part of the mix. A different mix would shift the ranking.
* **Not an external validation.** RELIC v1.1/V2 were developed on the old benchmark; SemBench is newer but authored within the project. No detector or normalisation rule was tuned after seeing SemBench; the normalisation rules and their SHA-256 are frozen; RELIC code is untouched.
* **The text rules' near-perfect recall is partly a property of the benchmark:** on the validated subset their false negatives are 0; all 15 misses of `normalized_text_A` on ALL (15 on ORACLE_DISAGREES) are cases whose label the oracle contests, i.e. possibly mislabelled changes that leave no textual trace.
* The normalised baseline's heuristics (continuation, in-stream data, comment-field detection) are not a JCL parser; see `NORMALIZED_TEXT_BASELINE.md`.
* The benchmark files changed once during this evaluation (179 → 180 cases; manifest re-hashed); all results here are from the final version identified by the hashes in §2, and `tests/sembench` fails if they go stale.
