## Known defects and how they are handled
1. **`l3_decomposition.json` field `L3_recomputed_gap` = −0.3362 is the L1 value.** Cause: line 48 of the original script calls `gap()` on the L1 labels. The paper does not cite this field; its L3 value (−0.170) is the last step of the chain, which was already correct. The original file is preserved unchanged. The corrected script writes `L1_gap` and `L3_gap` separately and asserts that the chain end equals an independently built L3 set (regression check). Corrected output: L1 −0.3362, L3 −0.17, n_L3 = 179.
2. **Tracked Groq raw output changed by two appended lines.** `results/final/llm/groq_gpt_oss_120b_raw.jsonl`: committed HEAD has 153 records; the working copy has 155 (appended `sembench_108` PRESERVING and `sembench_117` CHANGING). Both appended records are identical to the frozen snapshot (`results/final/llm/matched_subset_v1/frozen_raw_snapshot.jsonl`, sha 0a40b2c14bb488fe, 155 records, no duplicate IDs). The manifest's 155 matches the working copy, so the working copy is the experiment's output; the committed file is a 153-record prefix. None of the LLM results appear in the paper now. Do not commit this file without deciding whether the appended lines should be committed as a new record.
3. **Key-like strings in a tracked report.** `reports/v2/AGENT_6_RELEASE_AUDIT.md` (tracked) contains two strings beginning `gsk_` (Groq key format). I did not print them, and I did not edit the file, because it is a historical report. The key pasted in chat earlier must be treated as exposed: rotate it, then redact the file in a separate, reviewed commit.
4. **Table II rounding error (corrected in this pass).** The L1 text-B lower bound was printed as 0.665; the unrounded value is 0.665541, which rounds to 0.666. The earlier tie-tolerant checker accepted 0.665 because it allowed a 0.0006 tolerance. Corrected in the source and both PDFs; the new verifier checks the PDFs directly.
5. **Deduplication rule.** "Keep one copy" uses the first ID in sorted order within each (original hash, transformed hash) group. The dedup gap is −0.3375 under this rule (saved output −0.338 at three decimals). Other copy-selection rules were not tested; the manuscript's claim is that deduplication has little effect, which is consistent with this result only.
6. **MCC convention.** The original decomposition script returns 0.0 for an undefined MCC; the bootstrap returns NaN and drops undefined replicates. No reported point MCC has an undefined denominator, so this does not affect any reported value.

## Rounding convention in the final manuscript
Three decimals, round-half-up of the unrounded value, for MCCs, deltas, intervals and p-values. Two values are shown to four decimals because they sit near a rounding boundary: the leave-one-program-out range (−0.3645 to −0.3134) and the deduplication gap (−0.3375).
